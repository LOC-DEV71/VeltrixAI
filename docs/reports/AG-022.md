# AG-022 — Implementation and verification

Implemented database-backed configuration for Free, Basic Student, Plus and Pro.
The admin runs locally at http://localhost:5174/ and requires OWNER/ADMIN access.

- Admin: plan table, eight tabs, six dedicated Content & AI cards, field units/help,
  effective preview, validation, unsaved-change warning, diff, confirmation,
  optimistic version checks, audit history, archive and rollback.
- Backend: normalized schema, immutable revision/audit application interfaces,
  protected CSRF routes, public/effective plan APIs and idempotent bootstrap.
- Admission and workers: snapshotted costs/policies, transactional quotas/storage,
  rate limits, priorities, shared concurrency claims and stable entitlement errors.
- Content: explicit split/prompt jobs, history retention, output/scene limits,
  prompt-only preservation of narration/audio and safe claim-loss handling.
- TTS/clone: configured text/character/duration/voice/enrollment limits, old-job
  replay/credit safety and versioned credit grants/rollover.
- Client: dynamic AI/TTS limits and fees; docs/policies read the current catalogue.

testing previews configuration without publishing changes to real plan settings.

Deployment contract and material limits are documented in
[PLAN_CONFIGURATION.md](../PLAN_CONFIGURATION.md). In particular, production
database roles must prohibit revision/audit updates and deletion, and the current
TTS engine retains its infrastructure limit of 3000 characters per inference.
Catalogue pricing is not a payment/subscription implementation.
