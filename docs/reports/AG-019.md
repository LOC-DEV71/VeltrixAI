# AG-019: System voices and database voice selection

Follow-up: five more verified presets and Veltrix TTS listening samples are now available, making six system voices. See [VOICE_PREVIEWS.md](../VOICE_PREVIEWS.md). The single-voice counts below describe the initial AG-019 acceptance.

The backend now stores real system voices in `voices`. The previous static six-voice list has been removed. Only the already tested Hai Dang preset is initially seeded and ACTIVE.

The exact provider ID is `Hải Đăng`, not `Hai Dang`, `hai_dang` or an invented `sv_*` ID. It is the default preset in `vieneu==3.8.3`, `vieneu/assets/voices_v3_turbo.json`, from pinned source commit `85344322b7258b4e25479b692e8e3396baf9db34`. The saved wheel's JSON and pinned source JSON were compared byte-for-byte. SHA256: `e1f13cd2c2e0d29fdab5e15bfd7a30f3d7b768e6132bb43dd2b853f8efefdce9`. Its male metadata, speaker embedding and codec reference codes are present.

The artifact contains 25 presets. Their exact names and gender/description metadata are recorded in [preset-catalog.json](../../services/tts/preset-catalog.json); the other 24 are inventoried, not seeded/activated or claimed audio-tested. No model download or Internet lookup is performed by the seed or inference requests.

## Seed and migration

Run `pnpm --filter @creatorai/backend-api seed:voices`. The seed reads the local pinned artifact under `services/tts/artifacts` (or existing `TTS_BUNDLE_PATH`), checks the pinned JSON checksum, initializes the unique `(provider, providerVoiceId)` index and upserts one voice using `$setOnInsert`. Existing status, entitlement and metadata are preserved: rerunning cannot reactivate a REVOKED voice.

Seeded fields: `provider=VIENEU_LOCAL`, `providerVoiceId=Hải Đăng`, `name=Hải Đăng`, `language=vi-VN`, `gender=male`, `planEntitlements=["*"]`, `status=ACTIVE`, `isSystem=true`, `isDefault=true`. `*` means this system preset is available on every plan; it still incurs the normal TTS credit cost. Uniqueness is enforced by the database, not an application count check.

There was no existing backend subscription/plan source. `User.plan` is now server-owned with default `FREE`; old users without a stored plan are treated as FREE. Paid credit balance and roles do not grant a plan. A future billing integration must update this field; no billing/purchase endpoint is introduced here. Voice entitlement checks compare the exact persisted plan or `*`, both during request creation and Worker execution/publication.

For an older deployment with AG-018 queued jobs, stop the old Worker and run `node apps/backend-api/dist/scripts/seedSystemVoices.js --migrate`. The optional idempotent migration maps exact known system preset names to their database IDs, removes the legacy `payload.voice`, upgrades pending jobs to `pipelineVersion=2`, and backfills absent user plans. Unknown legacy voices receive no invented ID: the v2 Worker fails them and releases their reservation. The migration refuses active legacy execution leases; existing completed/failed jobs are untouched. Plain seed does not migrate jobs or update users. Local read-only preflight found zero legacy queued/processing jobs, so this deployment needed only the seed.

## Frontend contract

`GET /api/voices` requires the authenticated cookie and returns the existing envelope `{ success: true, data: { systemVoices: [...], cloneVoices: [] } }`. Only ACTIVE system voices entitled to the authenticated user's plan are included. Each has `id` (database ObjectId), `name`, `provider`, `language`, `locale`, `gender`, `planEntitlements`, `status`, `isDefault`, `isFree`, `tags`. `isFree` indicates FREE-plan eligibility, not zero credit cost. `providerVoiceId` is kept internal. Request query/body plan values are ignored.

Choose the voice with `isDefault=true` from this response and submit:

```http
POST /api/scenes/:sceneId/tts
Idempotency-Key: a-unique-operation-key
X-CSRF-Token: <matching csrf cookie>
Content-Type: application/json

{ "voiceId": "<id from GET /api/voices>" }
```

`voiceId` is required. The API rejects named `voice`, `providerVoiceId`, omitted voiceId or malformed IDs with `400 INVALID_INPUT`; it never trusts a client provider mapping. Idempotency now compares sceneId/voiceId, including normalized ObjectIds. An ACTIVE voice outside the user's plan returns `403 TTS_VOICE_PLAN_DENIED` before reserve. A syntactically valid missing/REVOKED voice produces a queued job which the Worker marks FAILED, releases once and creates no media.

Worker resolves the voice from the database before inference, rechecks after inference and inside publication's Mongo transaction. A write to the voice document fences concurrent revocation against publication. Completed Scene stores both `voiceId` and `ttsAudioId`. Errors include `TTS_VOICE_NOT_FOUND`, `TTS_VOICE_REVOKED`, `TTS_VOICE_PLAN_DENIED`, `TTS_VOICE_PROVIDER_UNSUPPORTED`, `TTS_VOICE_CHANGED`. Failed jobs release credits idempotently; generated Cloudinary files are cleaned up if publication fails. The polling and protected playback contracts from AG-018 remain unchanged.

## Local acceptance

`pnpm --filter @creatorai/backend-api test:tts` covers plan filtering, request validation, database resolution, missing/revoked/plan-denied voices, revocation during inference/publication, credit release and the existing provider/worker safeguards.

`node apps/backend-api/scripts/test-tts-local.cjs` starts the real VieNeu model and separate Worker, uses real Mongo transactions and Cloudinary authenticated storage, verifies repeated seed/request/settlement/refund and GET voices authentication, and deletes only its own temporary fixtures/private upload. Evidence is under `services/tts/offline-output/ag019`; the valid default system voice remains seeded. The WAV is downloaded through protected backend playback and additionally decoded/played with Windows SoundPlayer; `playback.json` binds playback evidence to its SHA256. Existing `.env` files are unchanged.

Final results: monorepo build and configured typechecks PASS; 55 tests PASS (25 voices/TTS plus 30 content/project regressions). Real-service acceptance reports `full_flow_pass=true`, including seed replay, database voice listing, one hold for concurrent requests, one settlement for completion replay and one release for missing/REVOKED voices. Temporary fixtures/private test upload were removed. Default-voice WAV: 460844 bytes, 4.8 seconds, 48000 Hz mono PCM16, SHA256 `70879608d452d97763cb4db95c69323d023e74ad86111d6cc57494ce7eb70e6c`; Windows decoder and PlaySync PASS.
