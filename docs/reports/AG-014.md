# Báo cáo Nhiệm vụ AG-014: Dynamic Config Credit & Fix lỗi Auth (Zombie Process, CORS, Mongoose)

## 1. Hệ thống Cấu hình động (Dynamic Config) cho Credit
- Khởi tạo model `SystemSettings` trong MongoDB để lưu cấu hình toàn hệ thống (AppConfig).
- Cập nhật service `CreditService.grantFreeCredits`:
  - Không còn hardcode số credit cấp miễn phí hàng tháng (ví dụ 2000).
  - Tự động query giá trị từ `SystemSettings` (key: `FREE_GRANT_AMOUNT`).
  - Nếu bản ghi chưa tồn tại, hệ thống tự động sinh bản ghi mặc định là 2000.
  - Cho phép Admin update DB dễ dàng để thay đổi mức thưởng cho các user đăng ký sau.
- Tích hợp gọi `grantFreeCredits` trực tiếp vào `AuthController` ở 2 luồng: `googleLogin` và `verifyOtp` khi khởi tạo User mới. 

## 2. Bảo mật Google Auth (Client ID Validation)
- Triển khai xác thực chặt chẽ `audience` trong `googleLogin`.
- Đảm bảo `client.verifyIdToken` chỉ chấp nhận token có `audience` khớp với biến môi trường `process.env.GOOGLE_CLIENT_ID`.
- Ngăn chặn hoàn toàn lỗ hổng sử dụng ID Token từ một Ứng dụng/App khác (Cross-client attack), trả về lỗi `Wrong recipient` nếu cố tình bypass.

## 3. Khắc phục triệt để các lỗi hạ tầng (Infrastructure Fixes)
- **Lỗi Timeout Mongoose:** Khắc phục lỗi `MongooseError: Operation buffering timed out` do file `src/index.ts` bị thiếu câu lệnh khởi tạo kết nối DB (`mongoose.connect(process.env.MONGODB_URI)`).
- **Lỗi Zombie Process (Port in use / 500 Error):** Phát hiện và kill toàn bộ các tiến trình Node.js chạy ngầm gây đụng độ cổng mạng và gián đoạn API.
- **Lỗi CORS (CSRF Token):** Thiết lập `exposedHeaders: ['x-csrf-token']` trên backend để frontend có thể đọc được token bảo mật. Sửa vòng lặp infinite reload trên frontend (`AuthContext.tsx`) do lỗi không tìm thấy token.
