# CDX-001 — Prompt Creator và API scenes

Ngày: 2026-10-01. Vai trò: Codex / Backend Developer.

## Kết quả

- Gemini `gemini-3.1-flash-lite` dùng systemInstruction riêng: Hook 3–5 giây, Body nhanh/súc tích, CTA tự nhiên; narration/title tiếng Việt, imagePrompt/videoPrompt tiếng Anh. Tham số user được JSON-encode vào user prompt, không nối vào system instruction.
- Bật `responseMimeType: application/json` và responseSchema dạng array trong SDK hiện có. Không thay SDK/dependencies.
- Parser chấp nhận JSON array, trích array cân bằng từ markdown/prose và sửa dấu phẩy thừa ngoài chuỗi. Không eval, không tự dựng nội dung khi output rác; kiểm tra tất cả trường, số cảnh và thời lượng trước khi ghi DB.
- Lưu title vào Scene. Gán order bằng backend và id bằng ObjectId DB.
- Thay content/cảnh trong Mongo transaction; lỗi parse không thay cảnh cũ. Lỗi xử lý đánh dấu job FAILED; lỗi hoàn credit không ngăn ghi trạng thái FAILED.
- `GET /api/contents/:id/scenes` kiểm tra xác thực/quyền sở hữu, trả `{ success: true, data: { scenes } }`. Mỗi scene có đúng id, order, title, narration, estimatedDuration, imagePrompt, videoPrompt.
- Job COMPLETED cũng có `result.scenes` cùng format; GET content hiện có giữ cấu trúc tương thích cũ.

Contract cụ thể và các trường hợp lỗi đã ghi trong `docs/API_CONTRACT.md`, mục CDX-001.

## Điểm nghiệm thu còn lại

Khi có môi trường thật: tạo job, poll đến COMPLETED, đối chiếu scene IDs/order/title giữa job result và GET scenes; kiểm tra chất lượng Hook/Body/CTA và ngôn ngữ hai visual prompts. Unit tests xác nhận cấu hình prompt và cấu trúc, không chứng minh chất lượng sáng tác của model thật.

Mongo replica set là điều kiện để transaction ghi cảnh và credit hoạt động. Việc ghi cảnh và quyết toán credit hiện là hai transaction riêng; chưa bảo đảm tính nguyên tử xuyên suốt cả hai khi DB/worker bị ngắt giữa chừng. Đây là giới hạn hạ tầng/lifecycle hiện tại cần nghiệm thu queue thật riêng.
