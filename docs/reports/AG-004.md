# Báo cáo Nhiệm vụ AG-004: Triển khai Auth và Chốt Data Model v0.3

## 1. Mục tiêu
Cập nhật tài liệu DATA_MODEL, API_CONTRACT, JOBS_AND_CREDITS lên v0.3. Triển khai code logic Authentication (Google, OTP, Refresh Token Rotation, Cookie-only, CSRF) cho Backend API và kèm theo các unit test.

## 2. Tài liệu & Thiết kế đã cập nhật (v0.3)
- Đưa khái niệm `credit_lots` và `credit_reservations` vào quản lý Credit thay cho chỉ `available/reserved` thô.
- Giải quyết bài toán Idempotency của worker bằng `executionClaim` (tránh rủi ro worker treo response chậm ghi đè lên kết quả worker retry).
- Cập nhật quy tắc xử lý khi Voice bị Revoke (kiểm tra trước inference và trước publish).
- Chuẩn hóa hệ thống Device ID với Free Grants (Asia/Ho_Chi_Minh).

## 3. Mã nguồn đã triển khai (Backend Auth)
- Cài đặt `google-auth-library`, `cookie-parser`, `jsonwebtoken`.
- **Utils**: `crypto.ts` (HMAC, Token Generator), `jwt.ts` (AccessToken).
- **Models**: `User`, `Session`, `OtpChallenge`, `LinkingContext` (chuyển sang logic session).
- **Middlewares**: `authMiddleware.ts` (kiểm tra accessToken/session và user status), `csrfMiddleware.ts` (Double-Submit Cookie Pattern cho CSRF).
- **Controller**: `AuthController.ts` với các tính năng:
  - `googleLogin`: Xác minh `idToken` bằng Google OAuth2 Client, tìm kiếm sub. Cấp `accessToken` và `refreshToken`.
  - `requestOtp`: Cấp challengeId và băm mã, không log terminal (Mock gửi email). Rate limit/Resend invalidate challenge cũ.
  - `verifyOtp`: Xử lý atomic attempts, compare HMAC.
  - `refresh`: Cơ chế Rotation Compare-and-Swap (Transaction). Detect Reuse Token (thu hồi Family). Trả 409 nếu rơi vào cửa sổ đồng thời (Race Condition).
  - `logout`: Revoke theo ID, clear cookies.
- **Bảo mật**: Mọi Token được lưu thông qua `HttpOnly`, `SameSite=Lax` Cookie.
- **Kiểm thử**: Viết unit test cho utils bằng `vitest` và đảm bảo tỷ lệ Pass 100%.
